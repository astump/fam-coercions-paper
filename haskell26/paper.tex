\section{Introduction}
\begin{enumerate}
  \item In Haskell, effects are modeled by functors T A
    equipped with useful typeclass instances like Applicative or Monad.
  \item Across modules, the functor in use varies with the collection of necessary effects.
  \item A front-end that does I/O will need to use a functor that supports IO,
    but pure computations might not use a functor at all.
  \item At a boundary between two modules, calls need to be decorated with
    liftings between their respective functors; if no such lifting exists
    then the calling module may need to be reorganized around a new functor that
    subsumes the old ones.
  \item While altering the types in use requires human input,
        inserting lift operations seems mechanical.
  \item In this paper, we automate the insertion of fmap lifts with
    a subtyping discipline that makes \(A \to B\) a subtype of \(FA \to FB\).
  \item The subtyping judgement is \emph{coercive}:
    each subtyping \(A \leq B\) comes with a function \(c : A \to B\)
    that is inserted during type checking.
  \item Despite the power of the fmap rule, the subtyping judgement remains
    coherent: for a given \(A\) and \(B\), all coercions \(c : A \leq B\) are
    equivalent.
  \item Our proof, checked in Agda, is a normalization proof for coercions
    that avoids the use of a small-step reduction relation.
  \item Instead, it achieves normalization by evaluation:
    coercions are mapped to a domain of normal forms, which can be reified back
    into coercions.
  \item The system of coercions in normal form \(n : A \leq B\)
    can also serve as an algorithmic subtyping judgement:
    it admits transitivity and reflexivity, but has unique derivations.
  \item Besides giving some confidence in the safety of this programming model,
    the proof of soundness has independent interest as a case study in
    normalization by evaluation and it makes good use of Agda's dependent
    pattern matching features.
\end{enumerate}
