\begin{abstract}
Programming with typeclass-defined combinators like fmap allows programs a
great deal of generality and concision, but programmers have to explicitly
invoke combinators in the right places in order to get their programs to type
check. In this paper, we propose inferring these operations using a coercive
subtyping discipline. It infers where to insert operations by looking for
points in the program where types do not yet agree but can be made to line up
by adding coercions. For functors, we promote the fmap combinator
\(\ltfmap : (A \to B) \to \F A \to \F B \) to a coercion
\(\cfmap : A \to B \subty \F A \to \F B\). We incorporate it into a monomorphic
system of coercions for base types, arrow types, and functor types. We
prove that the resulting system of coercions is coherent, meaning that all
possible choices of coercions from \(A\) to \(B\) end up equivalent. The proof
of the theorem is based on coherence by normalization, an approach to
coherence proofs based on the well-known technique of normalization by
evaluation.  All definitions and theorems in the paper are checked in Agda,
which played a valuable role in the design of the system.
\end{abstract}

\keywords{subtyping, functors, normalization by evaluation}

\section{Introduction}
Typeclass abstractions like Functor, Applicative, and Monad are essential to
modern functional programming.
%
The liberal application of type class combinators allows
concise generic programming even in the presence of
complex effects and data structures.
%
For example, consider writing a Haskell program that increments integers wrapped
in a \verb|Maybe| type.
\begin{Verbatim}
incrMaybe :: Maybe Int -> Maybe Int
incrMaybe (Just x) = Just (succ x)
incrMaybe Nothing  = Nothing
\end{Verbatim}
This naive definition of \verb|incrMaybe| has to unwrap its argument with
a pattern match and then wrap its output back up.
A more idiomatic definition uses \verb|<$>|, the fmap combinator, which
handles the unwrapping and wrapping. This has the added benefit of being
polymorphic, as it will work for any other instance of the Functor typeclass.
\begin{Verbatim}
incrMaybe :: Maybe Int -> Maybe Int
incrMaybe x = succ <$> x
\end{Verbatim}
In the presence of sufficient type information, we are interested in further
reducing the boilerplate involved by making fmap completely implicit. This would
permit implementing \verb|incrMaybe| just as one would want to write it, with no
use of fmap at all.
\begin{Verbatim}
incrMaybe :: Maybe Int -> Maybe Int
incrMaybe x = succ x
\end{Verbatim}
Given the declared type, there is really only one way to make this program make
sense.  It does not typecheck otherwise, so what would be the harm in inserting
an fmap? Automatically lifting functions to operate on arrays and other data
structures is already prevalent both in programming languages and informal
mathematical notation. By the same token, programming with more specific
abstractions like applicative functors~\cite{mcbride2008applicative} and monads
could also be made simpler by rendering combinators like \texttt{bind} and
\texttt{seq} implicit.

However, adding new implicit behavior to programming languages may make their
semantics unstable and confusing. The semantics of these hidden combinators must
be made clear and predictable if they are to become an acceptable part of
functional programming practice. In other words, we need to do some metatheory.

First, we point out that these missing combinators ought to be viewed as
implicit coercions between types. Implicit conversions are special functions
that are inserted during type inference in order to make a program type check.
They are usually drawn from a restricted grammar.
Traditionally, coercions are used to permit programs to gloss over details like
numerical conversions, which are both tedious and predictable. Our systems of
typeclass combinators are more abstract, but (provided they are drawn from
lawful Functor instances) they ought to be predictable enought to be baked in to
the type checking process. Besides standard lemmas about type inference such as
completeness and principal typing, the chief metatheoretic property of interest
for coercive subtyping is \emph{coherence}: this says that whatever coercions
are inserted during type inference leave program meaning unchanged.

In this paper, we address the problem of inserting implicit typeclass operations
for the Functor typeclass with a system of coercions and establish a form of
coherence for the system.  This allows applying pure functions to values of
functor type without having to insert calls to fmap. We describe a combined
coercion and subtyping judgment \[
  c : A \leq B
\]
where the coercion \(c\) is drawn from a simple combinator calculus. The
coercions elaborate into terms in a functional programming language, but come
from a much simpler combinator calculus. We add a special coercion \[
  \cfmap : A \to B \subty \F A \to \F B
\]
which lifts its argument into the functor. The other coercions are standard
and include, for instance, the mixed-variance coercion \[
  \carr\ c_1\ c_2 : A \to B \subty U \to V
\]
that turns two coercions \(c_1 : U \subty A\) and \(c_2 : B \subty V\)
into a coercion between the appropriate arrow types.

The system of coercions is declarative, in the sense that it is a good
specification of what coercions ought to be available in the system, but its
derivations are nondeterministic. This presents two problems: a nondeterministic
subtyping judgment is not suitable for implementation and the coercions inserted
by two different determinizations may end up doing different things to the
program.

We solve both problems. First, we define an algorithmic subtyping system with
unique derivations. It is proved sound and complete with respect to the
declarative subtyping system.  Second, in order to get some assurance that this
system of coercions is safe, we give a proof of its coherence. Coherence,
in this context, says that any two coercions \(c_1, c_2 : A \subty B\)
are semantically equivalent, in a sense to be made precise later.
Our proof of coherence exploits the theory of normalization by evaluation,
in which a complicated equivalence is analyzed by identifying canonical forms
for its equivalence classes. In this case, the canonical forms are precisely the
coercions from the algorithmic subtyping judgment.

To summarize, our paper makes the following contributions.
\begin{itemize}
  \item Declarative and algorithmic coercive subtyping judgments for inferring missing uses of \(\cfmap\) in functional programs.
  \item An equivalence-preserving translation of coercion combinators into lambda calculus.
  \item A proof of soundness, completeness, and uniqueness for algorithmic coercions.
  \item A proof of coherence for declarative subtyping based on normalization by evaluation.
  \item A mechanization of all of the above in Agda.\footnote{References to Agda definitions are rendered in \agdachk{teal}. The file is available in the supplementary material.}
\end{itemize}

The types and subtyping rules at issue are shown in Figure~\ref{fig:calculus},
which shows a base type, arrow types, and functor types, along with the usual
subtyping rules for all of these and the new \textsc{Fmap} rule.  This is the
declarative system.  Everything is standard except \textsc{Fmap}, which permits
using functions \(A \to B\) at the lifted type \(\F A \to \F B\). This rule may
be iterated, permitting the use of a function at \(\F A \to \F B\),
\(\F \F A \to \F \F B\), and so on. These rules serve as a good specification of
the system, but they have practical and theoretical limitations.

The declarative rules are not suitable for an implementation because they are
not deterministic: too many rules apply to possible subtyping queries.  Besides
the fact that it is always possible to appeal to the \textsc{Trans} rule,
queries of the form \(A \to B \subty \F U \to \F V\)  must choose between
applying \textsc{Arr} and \textsc{Fmap}. The way the \textsc{Fmap} rule overlaps
with the arrow rule is the chief source of technical complications in the
sequel.

Declarative coercions (Fig.~\ref{fig:coe}) are nothing more than proof terms for
the declarative subtyping judgment. Playing fast and loose with Curry-Howard, we
will often refer to the ``type'' of a coercion: this refers to the subtyping
judgment \(A \leq B\), which is not a type in the object language. However, we
do provide a translation of coercions into the object language, and under this
translation \(A \leq B\) does become a type of functions from \(A\) to \(B\).

The ambiguity in subtyping derivations discussed above means that for a fixed
judgment \(A \leq B\) there may be many possible coercions \(c_1\), \(c_2\), and
so on. In the case of transitivity, the following pair of derivations
raises the question of associativity of composition.
  \begin{mathpar}
    \inferrule*{
      \inferrule*{c_1 : A \leq B \\ c_2 : B \leq C}{\ccomp{c_1}{c_2} : A \leq C} \\
      c_3 : C \leq D
    }{\ccomp{(\ccomp{c_1}{c_2})}{c_3}: A \leq D}

    \inferrule*{
      c_1 : A \leq B
      \inferrule*{c_2 : B \leq C \\ c_3 : C \leq D}{\ccomp{c_2}{c_3} : B \leq D} \\
    }{\ccomp{c_1}{(\ccomp{c_2}{c_3})}: A \leq D}
  \end{mathpar}
The ambiguity of the arrow rules leads to confusion between \(\cfmap\) and
\(\carr\). Together with composition, this produces another pair of possibly
inequivalent derivations. The first uses \(\cfmap\) after \(\carr\):
\begin{mathpar}
  \inferrule*{
    \inferrule*{c_1 : U \leq A \\ c_2 : B \leq V}{\carr\ c_1\ c_2 : A\to B \leq U \to V} \\
    \inferrule* {  }{\cfmap : U \to V \leq \F U \to \F V}
  }{\ccomp{\carr\ c_1\ c_2}{\cfmap} : A \to B \leq \F U \to \F V}
\end{mathpar}
The second uses \(\cfmap\) before \(\carr\):

Keeping these examples in mind, we now discuss the implications of ambiguity in
subtyping derivations.
Under a coercive subtyping discipline, type inference becomes an elaboration
pass that walks an untyped term \(e\), inserting coercions as it goes, to
construct a typed term \(e'\). In theoretical terms, the type system has a
judgment shaped like \(\Gamma \vdash e \rightsquigarrow e' : A\) where \(e\) is
an input and \(e'\) is an output. It appeals to a subtyping judgment
\(c : A \subty B\) that emits a coercion \(c\), which is brought back into
the grammar of terms by a translation \(\cc{c} : A \to B\). This is all tied together
in the subsumption rule:
\[
  \inferrule*[Left=Sub]{
    \Gamma \vdash e : A\\
    c : A \subty B
  }{
    \Gamma \vdash e \rightsquigarrow \cc{c}\ e : B }
\]
This process may alter the semantics of \(e\), if they are even defined at all.
But there is another problem. In a declarative type system there are, in general,
many derivations of the same typing judgment. When dealing with coercive subtyping,
this means that while there is generally a unique derivation for a fixed pair of
\(e\) and \(e'\), there may be many possible choices of \(e'\) from the same
initial \(e\). This means that different implementations of the same type system
could give different semantics to the same program.

\paragraph{Coherence for subtyping and elaboration}
To ensure the meaning of a program is stable across all possible typing
derivations, language designers prove \emph{coherence}.  A subtyping judgment is
coherent when all coercions \(c : A \subty B\) between the same types are
semantically equivalent.  This means that every path in the ``coercion graph''
is equivalent or, to borrow a category-theoretic slogan, ``all diagrams
commute.'' The elaboration judgment is coherent when all \(e'\) with
\(\Gamma \vdash e \rightsquigarrow e' : B\) are semantically equivalent and
furthermore \(e\) is semantically equivalent to \(e'\).
Of course, nobody ever runs code that was elaborated by a declarative type
system. Instead, implementations of type inference will hew closely to an
algorithmic type system including a system of coercions \(c_a : A \asubty B\).
By virtue of being
algorithmic, this system will have unique coercions and emit unique elaborated
terms.  It enjoys subtyping coherence automatically because its coercions and
elaborated terms are not merely equivalent, but equal.

This is not a shortcut to solving the coherence problem.  However expedient it may be to
determinize everything in sight, it will end up costing more in the long term.
There are many perfectly reasonable algorithmic typing judgments (and
implementations) associated to any one declarative system. A
Damas-Hindley-Milner system will produce different derivations than one based on
bidirectional typing, and so on.  A future algorithmic type system with its own
idiosyncratic solution to the problem of determinizing the rules will include
its own typed grammar of coercions \(c_b: A \bsubty B\) and its own elaboration
judgment. In order to show these have anything to do with the other coercions
\(c_a : A \asubty B\), we need a common semantics in which to compare them.
Without a declarative system, our only option is try and prove a contextual
equivalence \[
  \cca{c_a} \approx \ccb{c_b}.
\]
Needless to say, this is not a direct route. Since the invariants the two
algorithmic type systems exploit in order to determinize the rules of the
declarative system are likely to be different, the coercions they produce
for a given query are unlikely to share any structural similarities.
On top of that, equational reasoning in the target language may be complex or
underspecified when compared to equational reasoning about coercions, which
ought to be terminating and effect-free programs.

\paragraph{Coherence by normalization: a recipe}
We propose coherence by normalization, a formulation of coherence for subtyping
that can exploit the benefits of choosing a distinguished algorithmic system
without requiring future algorithmic systems to be related directly to it.
Rather than defining coercions only for a deterministic judgment, we begin from
a grammar of coercions \(c : A \subty B\) for the declarative system. These
combinators are equipped with an axiomatized equivalence relation
\(c_1 \coeeq c_2\).  The grammar will supply proof terms
for the judgment \(A \subty B\) without appealing to the grammar of the
programming language.  The equivalence relation will be finitely axiomatized, in
the style of abstract algebra, and will not appeal to the translation
\(\ccname\) of coercions into expressions. In order to justify the equivalence
relation, we check that the translation \(\ccname\) is sound:
\[
  c_1 \simeq c_2 \Longrightarrow
  \ccname(c_1) \approx \ccname(c_2)
\]

We then define an algorithmic system \(n : A \nsubty B\) of \emph{normal coercions},
so named because they will be used to put (declarative) coercions into normal form.
These will enjoy unique derivations. In order to prove coherence, we begin by
saying how to translate coercions into normal form and back:
\begin{align*}
  \evalname &: A \subty B \to A \nsubty B \\
  \reify &: A \nsubty B \to A \subty B
\end{align*}
That \(\evalname\) and \(\reify\) can be defined at all constitutes proof that
the normal system is sound and complete with respect to the declarative system.
The next step in normalization by evaluation is to prove that
\(\reify (\eval c) \coeeq c\).
By exhibiting a left inverse, we show that \(\evalname\) is injective up to
equivalence. This implies coherence, since we know \(\eval{c_1} = \eval{c_2}\)
from the uniqueness theorem for normal coercions.

\paragraph{Extending the recipe with a new implementation}
Consider the situation now for a future algorithmic judgment
\(c_a :  A \asubty B\). We already know declarative coercions are coherent, so
we just need to know that in the new system of coercions each \(c_a\) is
equivalent to a declarative coercion \(c\). All we have to do is define another
pair of functions
\begin{align*}
  \evalname_{\mathsf{a}} &: A \subty B \to A \asubty B \\
  \reify_{\mathsf{a}} &: A \asubty B \to A \subty B,
\end{align*}
This time around, the equivalence
\(\reify_{\mathsf{a}}\ (\evalname_{\mathsf{a}}\ c) \equiv c\) follows from the
coherence result that was already proved.  It does have to be checked that
\(\cca{c_a} \approx \cc{\reify_{\mathsf{a}}{c_a}}\), but this can always be
taken as a definition of \(\cca{c_a}\).

\paragraph{Comparison to Reynolds' method}
The coherence problem was studied as early as 1980 by
Reynolds~\cite{reynolds80}, who outlined an algebraic approach to coherence of
elaboration that complements our own. It was Reynolds who recognized that
coercions form a \emph{category}: there are types \(A, B, \dots\) and between
any two types there is a set of coercions \(\coe(A, B)\). There should always be
identity coercions \(\id_A \in \coe(A, A)\), which do nothing, and an
associative and unital composition operation
\(\circ : \coe(B, C) \times \coe(A, B) \to \coe(A, C)\).
Reynolds assumed that coercions form a preorder, that is, for every pair of
arrows \(c1, c2 \in \coe(A, B)\), \(c1 = c2\). While this is true (up to
equivalence) for any coherent coercive subtyping relation,
our approach to coherence is a robust technique for establishing it in the first
place.

\section{Defining and justifying the equational theory}
The first order of business in establishing coherence is to decide on a
reasonable definition of equivalence for coercions. As mentioned above, we take
an algebraic approach and define an equivalence using a short list of axioms.
It helps that coercion combinators appear to form a category, so the appropriate
axioms are, for the most part, easy to guess.

\begin{definition}[Coercion congruence]
  The equivalence relation \(\coeeq\) is the least congruence obeying the following laws, which are implicitly universally quantified.\\
\begin{minipage}{0.4\textwidth}
\begin{align*}
\ccomp{\cid{}}{c} &\coeeq c \\
\ccomp{c}{\cid{}} &\coeeq c \\
\ccomp{c_1}{(\ccomp{c_2}{c_3})} &\coeeq \ccomp{(\ccomp{c_1}{c_2})}{c_3} \\
\cmono\ (\cid{A}) &\coeeq \cid{\F A}
\end{align*}
\end{minipage}
\begin{minipage}{0.5\textwidth}
\begin{align*}
\cmono\ (\ccomp{c_1}{c_2}) &\coeeq \ccomp{\cmono\ c_1}{\cmono\ c_2} \\
\carr\ \cid{A}\ \cid{B} &\coeeq \cid{A \to B} \\
\carr\ (\ccomp{c_1}{c_2})\ (\ccomp{c_3}{c_4}) &\coeeq
\ccomp{\carr\ c_2\ c_3}{\carr\ c_1\ c_4} \\
\ccomp{\cfmap}{\carr\ (\cmono\ c_1)\ (\cmono\ c_2)} &\coeeq \ccomp{\carr\ c_1\ c_2}{\cfmap}
\end{align*}
\end{minipage}
\end{definition}
In order, the laws say that coercions form a category, \(\cmono\) is a functor
on that category, and \(\carr\) is a bifunctor on that category.  The final law,
which we refer to as the \emph{special fmap law}, is unusual becuase \(\cfmap\)
is not a functor on coercions but instead a functor on types. In the equational
theory of coercions, all that can be said about \(\cfmap{}\) is how it interacts
with other coercions on arrow types. No rule is needed to describe how it
interacts with \(\cfmap{}\), since \(\cfmap \cdot \cfmap\) is, in general, only
equal to itself. The special fmap law implies the last pair of ambiguous derivations shown
in Section~\ref{sec:overview} is coherent.

\subsection{Compiling coercions correctly}
In order to justify the equational theory, especially the new fmap law, and show
that these coercion combinators can be soundly compiled to a programming
language, we provide a translation into typed lambda calculus equipped with an
abstract functor \texttt{F}.  Then we prove that the translation preserves
equivalence, which is given by the equational theory in the source language and
by \(\beta\eta\)-equivalence, function extensionality, and fmap laws in the target.\\
\begin{minipage}{0.5\textwidth}
\begin{align*}
  \cc\tbool &= \ltbool \\
  \cc{A \to B} &= \cc{A} \ltarr \cc{B} \\
  \cc{\F A} &= \ltf \cc{A} \\
\end{align*}
\end{minipage}
\begin{minipage}{0.5\textwidth}
\begin{align*}
  \cc{\cid{A}} &= \lambda x : \cc{A}.\, x \\
  \cc{\ccomp{c_1}{c_2}} &= \lambda x.\,\cc{c_2}\ (c_1\ x) \\
  \cc{\carr\ c_1\ c_2} &= \lambda f\, x.\,c_2\ (f\ (c_1\ x)) \\
  \cc{\cmono\ c} &= \ltfmap\ \cc{c} \\
  \cc{\cfmap} &= \ltfmap
\end{align*}
\end{minipage}

\begin{proposition}[\agdachk{interp-sound}]
  For all \(c_1, c_2 : A \subty B\), \[
    c_1 \coeeq c_2 \Longrightarrow \cc{c_1} \equiv_{\beta\eta\ltf} \cc{c_2}
  \]
\end{proposition}
\begin{proof}
  By induction on \(c_1 \coeeq c_2\). Extensionality appears necessary in the case for the special fmap law.
\end{proof}

\section{Algorithmic judgment and normal coercions}
Using the equational theory, we now design the algorithmic system. The idea is
to remove the \textsc{Refl} and \textsc{Trans} rules and instead devise a system
where they are admissible. We also need to address the overlap between the fmap
and \(\narr\) rules.  Our solution is shown in Figure~\ref{fig:ncalculus}.
We will sometimes elide the proof terms \(n\) and \(\na\) and just refer to the
subtyping judgments \(A \nsubty B\) and \(A, B \nasubty U, V\).
We separate the system into normal coercions \(n : A \nsubty B\) and arrow
coercions \(\na : A, B \nasubty U, V\). The normal coercions have exactly one
rule for each type former. The arrow coercions include \(\naarr\), which
performs ordinary mixed-variance arrow subtyping by appealing to two normal coercions,
and \(\mathsf{nfmap}\), which extends an arrow coercion with one use of fmap on the right.

\subsection{Uniqueness of normal coercions}
It is not immediately clear that normal coercions have \(n_1 = n_2\) for any
\(n_1, n_2 : A \nsubty B\).  The proof of this ought to look like an induction
on one paired with some inversion lemmas on the other, but there are issues in
the arrow cases. For instance, inverting \(\na_2 : A, B \nasubty \F U, \F V\)
suggests that \(na_2\) has the form \(\na_2 = \nfmap{\na'}\) or
\(\na_2 = \naarr\ n_1'\ n_2'\), but both options are possible.
Fortunately, there are some invariants preserved by subtyping that will allow
ruling out the latter possibility.

The subtyping relations \(A \nsubty B\) and \(A, B \nasubty U, V\) exhibit
a predictable relationship between the number of leading functors in
the types on their left and right. To this point, define the \emph{peel number} of a
type to be  \(\peel{\F A} = 1 + \peel A\) and \(\peel A = 0\) otherwise.  The
peel number is preserved by normal subtyping and increased by arrow subtyping.
\begin{proposition}[Peel invariants]\label{prop:peel}
  Let \(A, B, U\), and \(V\) be types.
  \begin{enumerate}
    \item If \(A \nsubty B\) then \(\peel A = \peel B\).
    \item If \(A, B \nsubty U, V\) then \(\peel A + k = \peel U\) and \(\peel B + k = \peel V\) for some \(k\).
  \end{enumerate}
\end{proposition}
\begin{proof}
  By mutual induction on \(\nsubty\) and \(\nasubty\).
\end{proof}
With this in hand, we can distinguish arrow coercions. In fact, the \(k\) that
appears in the invariant for arrow subtyping counts the number of
\(\mathsf{nfmap}\) constructors that appear in the underlying arrow coercion
\(\na\).

\begin{proposition}[\agdachk{ncoe-uniq}]\label{thm:uniqueness}
  Let \(A, B, U\), and \(V\) be types.
  \begin{itemize}
    \item If \(n_1 : A \nsubty B\) and \(n_2 : A \nsubty B\) then \(n_1 = n_2\).
    \item If 
      \(\na_1 : A, B \nasubty U, V\)
      and
      \(\na_2 : A, B \nasubty U, V\)
      then 
      \(\na_1 = \na_2\).
  \end{itemize}
\end{proposition}
\begin{proof}
  By mutual induction on \(n\) and \(\na\). We show a couple of representative cases.
\begin{itemize}
  \item Case \(n_1 = \nmono\ n_1'\): By inversion, \(n_2 = \nmono\ n_2'\) and we can apply the IH.
  \item Case \(\na_1 = \nfmap{\na_1'}\) with \(\na_1' : A, B \nasubty U, V\):
        By Proposition~\ref{prop:peel}, we have \(\peel{A} \leq \peel{U}\).
        If \(\na_2 = \nfmap{\na_2'}\) then the IH applies. Otherwise,
        \(\na_2 = \naarr\ n_1\ n_2\) for some coercions \(n_1 : \F U \nsubty A\)
        and \(n_2 : B \subty F V\). Applying Proposition~\ref{prop:peel} again yields
        \(\peel{A} = \peel{U} + 1\), a contradiction.\qedhere
\end{itemize}
\end{proof}

\section{Coherence}
In this section, we prove that all coercions of the same type are equivalent. We
establish our result using the methods of normalization by evaluation, which is
more commonly used to derive decidable equality for a language by lifting it
from a model that is already equipped with an easily decidable equivalence
relation, like syntactic equality. In this section we establish coherence for
coercions by lifting it from a proof of uniqueness for normal coercions. In a
sense we are deriving a decidable equality that happens to always return true.
We are also, by virtue of working with a monomorphic combinator calculus,
dealing with a simpler system than normalization by evaluation is typically
applied to.

\subsection{Reification and evaluation}
Normal coercions are immediately interpretable as coercions, as exhibited by the
following straightforward definition of \(\reify\).
Note that the reification of \(\nfmap{\na}\) puts \(\cfmap\) after the
reification of \(\na\) and not before. This is an arbitrary choice, like the
choosing between cons lists and snoc lists. Putting \(\cfmap\) at the front
would affect the ``bias'' of subsequent proofs but all the top-level theorems
would say the same things.
\begin{align*}
  \reify\ \nid &= \cid{\tbool} \\
  \reify\ (\nmono\ n) &= \cmono\ (\reify\ n) \\
  \reify\ (\narr\ \na) &= \reifyna \na \\
  \reifyna\ (\naarr\ n_1\ n_2) &= \carr\ (\reify\ n_1)\ (\reify\ n_2) \\
  \reifyna\ (\nfmap{\na}) &= \ccomp{\reifyna \na}{\cfmap}
\end{align*}

Reification is sound because all functions preserve equality. By composition,
the induced translation
\(\ccname \circ \reify\)
into lambda calculus
is also sound. This means our syntactic equality agrees with the intended model.
The type of reify is also informative.
Read through Curry-Howard, it says that the normal subtyping
relation is sound (but not necessarily complete) with respect to declarative subtyping. \[
  A \nsubty B \Longrightarrow A \subty B
\]

The other direction amounts to a proof of completeness and is more complex.  It
is accomplished by the evaluation function, which turns a declarative coercion
into a normal coercion of the same type. It relies on two definable operators on
normal coercions.
\[
  \mkid{A} : A \nsubty A \qquad \mkcomp : A \nsubty B \times B \nsubty C \to A \nsubty C
\]
These correspond to standard lemmas in the metatheory of subtyping.
The first proves a reflexivity rule is admissible,
while the second proves a transitivity rule is admissible.
Evaluation uses these to establish the completeness of normal subtyping.
Promoting these results from theorems to functions makes them proof-relevant,
which will ultimately allow us to show a stronger result: implicit coercions in
both theories behave the same.

The identity and composition operators permit a structurally recursive
definition of \(\evalname\), which is otherwise defined in terms of constructors.
\begin{align*}
  \eval{\cid{A}} &= \mkid{A} \\
  \eval{(\ccomp{c_1}{c_2})} &= \mkcomp\ (\eval{c_1})\ (\eval{c_2}) \\
  \eval{(\cmono\ c)} &= \nmono\ (\eval{c}) \\
  \eval{(\carr\ c_1\ c_2)} &= \narr\ (\naarr\ (\eval{c_1})\ (\eval{c_2})) \\
  \eval{\cfmap} &= \narr\ (\nfmap{(\naarr\ \mkid{A}\ \mkid{B})})
\end{align*}
The identity operator is defined by induction on type. This helps explain why
the normal coercions do not have a built-in \(\nid_A\) operator for any type
\(A\), but only include it for base types. Otherwise, at every type \(A\) the
two distinct proofs \(\nid_A\) and \(\mkid{A}\) would both prove
\(A \nsubty A\), which would break uniqueness (Proposition ~\ref{thm:uniqueness}).
\begin{align*}
  \mkid{\tbool} &= \nid \\
  \mkid{A \to B} &= \narr\ (\naarr\ (\mkid{A})\ (\mkid{B})) \\
  \mkid{\F A} &= \nmono\ (\mkid{A})
\end{align*}

The composition operator is more complex. It deals with the mutually inductive
types of normal coercions and arrow coercions. While most clauses in the
definition below are straightforward structural recursion, there is a snag in
one case, which composes an arrow coercion ending in an fmap with another arrow
coercion. The available fmap constructor in the grammar for \(\na\) only puts
fmaps on the right, so we need to push the fmap ``through'' the second argument,
all the way to the end, and adjust the coercion to fit.

At a higher level, we are defining an operation that composes an arrow coercion
\(\na\) with an fmap on the left.
It has the type
\(\nfmapl : \F A, \F B \nsubty U, V \to A, B \nsubty U, V\)
and is defined by only two clauses.
\begin{align*}
\nfmapl\ (\nfmap{\na}) &= \nfmap{(\nfmapl{\na})} \\
\nfmapl\ (\naarr\ (\nmono\ n_1)\ (\nmono\ n_2)) &= \nfmap{(\naarr\ n_1\ n_2)}
\end{align*}
These rules are exhaustive. The trick here is that if \(\na\) is safe to compose
with an fmap on the left, it must have \(\F\) types in its domain(s). If it has
the form \(\naarr\ n_1'\ n_2'\), the only way the sub-coercions \(n_1'\) and
\(n_2'\) can be well-typed is by beginning with \(\nmono\).  This procedure,
which pushes an fmap through a term by ``demoting'' \(\nmono\) coercions,
can be justified by the special fmap law.

With that obstacle cleared, we can define composition for normal coercions by a
straightforward recursion.
\begin{align*}
  \mkcomp\ n_1\ \nid &= n_1 \\
  \mkcomp\ \nid\ n_2 &= n_2\\
  \mkcomp\ (\nmono\ n_1)\ (\nmono\ n_2) &= \nmono\ (\mkcomp\ n_1 n_2) \\
  \mkcomp\ (\narr\ \na_1)\ (\narr \na_2) &= \narr\ (\mkcompna\ \na_1\ \na_2) \\
  \mkcompna\ (\naarr\ n_1\ n_2)\ (\naarr\ n_3\ n_4) &= \naarr\ (\mkcomp\ n_3\ n_1)\ (\mkcomp\ n_2\ n_4) \\
  \mkcompna\  \na_1\ (\nfmap{\na_2})&= \nfmap{(\mkcompna\ \na_1\ \na_2)} \\
  \mkcompna\ (\nfmap{\na_1})\ \na_2 &= \mkcompna\ \na_1\ (\nfmapl\ \na_2)
\end{align*}
We have now fully defined the evaluation function \(\evalname\).
We record some immediate observations about its definition.  First, it has the
type it was claimed to have: it really does send proofs of \(A \subty B\) to
proofs of \(A \nsubty B\). This makes normal subtyping complete with respect to
declarative subtyping. This permits us to conclude evaluation respects equivalence.
\begin{proposition}[\agdachk{eval-sound}]
  For all \(c_1, c_2 : A \subty B\),
  if \(c_1 \coeeq c_2\) then \(\eval{c_1} = \eval{c_2}\).
\end{proposition}
\begin{proof}
  Since \(\eval{c_1}, \eval{c_2} : A \nsubty B\), this follows from the
  uniqueness of normal coercions at a given type (Proposition ~\ref{thm:uniqueness}).
\end{proof}

\subsection{Reification inverts evaluation}
Following the path blazed by normalization by evaluation, we will now prove that
\(\reify\) is a left inverse to \(\mathsf{eval}\). This makes \(\evalname\)
injective up to equivalence and will allow us to lift uniqueness for normal
coercions up to a proof of coherence for declarative coercions.  The proof of
this lemma exercises all the rules of the equivalence relation \(\coeeq\) on
coercions including the special fmap rule.

The first order of business is to establish that \(\reify\) is a homomorphism.
This means checking that each of the operations we defined on normal coercions
in the course of defining eval is sent to its counterpart in declarative
coercions. These results only hold up to equivalence.
\begin{proposition}[\agdachk{reify-mkid}]\label{reify-mkid}
  For all \(A\), \(\reify\ \mkid{A} \coeeq \cid{A}\).
\end{proposition}
\begin{proof}
  By induction on \(A\) using the identity laws for \(\cmono\) and \(\carr\).
\end{proof}

\begin{proposition}[\agdachk{reify-na-fmap-l}]
  If \(\na : \F A, \F B \nasubty U, V\) then
          \[\reifyna\ (\nfmapl\ \na) \coeeq \ccomp{\cfmap}{\reifyna\ \na}.\]
\end{proposition}

\begin{proposition}[\agdachk{reify-mkcomp}]\label{reify-mkcomp}
  Let \(A, B, U, V, X\), and \(Y\) be types.
  \begin{enumerate}
    \item For all \(n_1 : A \nsubty B\) and \(n_2 : B \nsubty C\),
  \[\reify\ (\mkcomp\ n_1\ n_2) \coeeq \ccomp{(\reify\ n_1)}{(\reify\ n_2)}.\]
    \item For all \(\na_1 : A, B \nasubty U, V\) and \(\na_2 : U, V \nasubty X, Y\),
          \[\reifyna\ (\mkcompna\ \na_1\ \na_2) \coeeq \ccomp{(\reifyna\ \na_1)}{(\reifyna\ \na_2)}.\]
  \end{enumerate}
\end{proposition}

Now we can prove that reify inverts evaluation. The interesting case, which
shows that \(\cfmap\) is equivalent to the round-trip \(\reify\ (\eval{\cfmap})\),
has to appeal to the special fmap law.
\begin{lemma}[\agdachk{reify-eval}]\label{reify-eval}
  If \(c : A \subty B\), then \(\reify\ \eval{c} \coeeq c\).
\end{lemma}
\begin{proof}
  By induction on \(c\).
  \begin{itemize}
    \item Case \(c = \cid{A}\): By Proposition~\ref{reify-mkid}.
    \item Case \(c = \ccomp{c_1}{c_2}\): By Proposition~\ref{reify-mkcomp} and the IH.
    \item Case \(c = \cmono\ c\): By the IH.
    \item Case \(c = \carr\ c_1\ c_2\): By the IH.
    \item Case \(c = \cfmap\): We reason equationally.
          \begin{align*}
\reify\ (\eval{\cfmap})&= \ccomp{\carr\ (\reify\ \mkid{A})\ (\reify\ \mkid{B})}{\cfmap} &\text{By definition}\\
            &\coeeq \ccomp{(\carr\ \cid{A}\ \cid{B})}{\cfmap} &\text{Proposition~\ref{reify-mkid}} \\
            &\coeeq \ccomp{\cfmap}{\carr\ (\cmono\ \cid{A})\ (\cmono\ \cid{B})} &\text{Special fmap law}\\
            &\coeeq \ccomp{\cfmap}{\carr\ \cid{\F A}\ \cid{\F B}} &\text{Identity law for \(\cmono\)}\\
            &\coeeq \ccomp{\cfmap}{\cid{\F A \to \F B}} &\text{Identity law for \(\carr\)}\\
            &\coeeq \cfmap &\text{Right identity law}
          \end{align*}
  \end{itemize}
\end{proof}

Coherence is an immediate consequence of the lemma.
\begin{theorem}[\agdachk{coe-coh}]\label{thm:coherence}
  If \(c_1, c_2 : A \subty B\) then \(c_1 \coeeq c_2\).
\end{theorem}
\begin{proof}
  We reason equationally since \(\coeeq\) is an equivalence relation.  The
  middle step uses equality, which is finer than \(\coeeq\) and respected by
  \(\reify\).
  \begin{align*}
    c_1 &\coeeq \reify (\eval{c_1}) & \text{by symmetry of \(\coeeq\) and normalization (Lemma~\ref{reify-eval})}&\\
    &= \reify (\eval{c_2}) & \text{by uniqueness (Proposition~\ref{thm:uniqueness})} &\\
    &\coeeq c_2 & \text{by normalization (Lemma~\ref{reify-eval})} &\qedhere
  \end{align*}
\end{proof}

\section{Implementation in Agda}
All of our definitions and theorems were implemented in Agda,
where we made heavy use of dependently typed syntax and dependent pattern matching
to keep our theorems concise and our proofs simple.
The presentation of the system in the paper glosses over details that were
checked by Agda, like the well-typedness of the output of the reification and
evaluation functions.

We found Agda well suited to the task of mechanizing normalization by evaluation
for coercions. All proof assistants are adequate for algebra over a single sort,
but in many-sorted and indexed algebras good pattern matching becomes indispensable.
Agda's dependent pattern matching allowed us to use an intrinsically typed syntax
and write concise proofs. In Agda, many cases in definitions by recursion which
we would otherwise have to prove impossible were actually automatically dispatched
by the pattern matching coverage algorithm.  In inductive proofs, this makes a
big difference in the usability of the system and the efficiency of formalizing
metatheory.

While reasoning about coercions, we rely on a user-defined equivalence relation
instead of Agda's propositional equality. While Agda has special ``rewrite
patterns'' for rewriting with equations on the left side of a pattern match, we
did not find the same level of built-in support for rewriting with custom
equivalences.  This means that our proofs end up containing big proof terms that
are littered with congruence and transitivity rules, like the following clause
from the proof of \texttt{reify-eval}. What this term really does is a series of
rewrites along \texttt{c-arr-fmap}, \texttt{reify-mkid}, \texttt{c-mono-id},
\texttt{c-arr-id}, and \texttt{c-id-r}, but it also has to declare where in the
term those rewrites happen and in what order.
\begin{Verbatim}
reify-eval (c-fmap {a} {b}) =
   c-trans (c-sym c-arr-fmap)
    (c-trans
      (c-cong-comp
        (c-refl c-fmap)
        (c-trans
          (c-cong-arr (c-trans (c-cong-mono (reify-mkid a)) c-mono-id)
                      (c-trans (c-cong-mono (reify-mkid b)) c-mono-id))
          c-arr-id))
      c-id-r)
\end{Verbatim}



\section{Perspectives and future work}
We have shown that coercive subtyping for functors is coherent. In the future,
we are hoping to extend these results to simplify programming with richer
abstractions, like applicative functors and monads.  These would permit more
sophisticated applications of the subtyping discipline, like in the following
example of an evaluator for a calculator language.
\begin{Verbatim}
data Exp = Const Int | Add Exp Exp | Mul Exp Exp | Div Exp Exp

maybeDiv :: Int -> Int -> Maybe Int
maybeDiv n1  0 = Nothing
maybeDiv n1 n2 = Just (div n1 n2)

eval :: Exp -> Maybe Int
eval   (Const n) = n
eval (Add e1 e2) = (+) <$> eval e1 <*> eval e2
eval (Mul e1 e2) = (*) <$> eval e1 <*> eval e2
eval (Div e1 e2) = do n1 <- eval e1
                      n2 <- eval e2
                      maybeDiv n1 n2
\end{Verbatim}
This program mixes uses of applicative and monad combinators, with applicatives
used for total operators and monads for the partial one. Under a subtyping
discipline that silently inserts monad and applicative combinators, it could
simply be written like this.
\begin{Verbatim}
eval :: Exp -> Maybe Int
eval (Const n) = n
eval (Add e1 e2) = eval e1 + eval e2
eval (Mul e1 e2) = eval e1 * eval e2
eval (Div e1 e2) = eval e1 `maybeDiv` eval e2
\end{Verbatim}

Unfortunately, there are a few immediate technical obstacles to achieving this
level of brevity in realistic programs while maintaining soundness,
decidability, and coherence.
A subtyping system for an applicative functor \(F\) should include the
declarative coercions \(\textsf{pure} : A \subty \F A\) and
\(\textsf{seq} : \F(A \to B) \subty \F A \to \F B\). Our normal coercions for
plain old functors do not immediately generalize to this setting. The peel
invariant (Proposition~\ref{prop:peel}) relied on in some proofs no longer holds
because both of the new coercions do not preserve number of leading \(F\)s in
types. These coercions introduce many more pairs of coercions that can be
composed, and designing a system of normal coercions that can choose a canonical
form for all these compositions will require further research.

We have not defined an algorithmic type inference judgment for our system
or proved it coherent. We expect this to be straightforward for a monomorphic
calculus with just fmap, but there are difficulties in extending the result to
polymorphic types.  Consider a program that applies \texttt{head : [a] -> a} to
a list of lists. It already typechecks and it returns the first list. But it is
also possible to insert an fmap, which will make it return a list of the head
elements of each list. This makes both of the following results plausible,
even though they clearly violate coherence.
\begin{Verbatim}
head [[1,2],[3,4]] = [1,2]
head [[1,2],[3,4]] = [1,3]
\end{Verbatim}
Making this work in general requires incorporating a notion of principal type
into the declarative typing judgment so that functions are only lifted when
necessary, but formulating this notion will require further work.

As far as proving the system coherent goes, we may be able to scale our method
of coherence by normalization to whole programs. While equivalence of programs
is undecidable in general, we only need normal forms that are sufficiently organized
in order to put two elaborations of the same source term into one shape.

The alternative is to deploy a logical relation in the style of Reynolds~\cite{reynolds00},
whose famous ``bracketing theorem'' relates an untyped semantics where subtyping
is interpreted by inclusion to a typed semantics where subtyping is interpreted
by coercion maps.
Here there
may be a snag. These logical relations relate an untyped semantics, where
subtyping is interpreted by inclusion, to a typed semantics, where subtyping is
interpreted by coercion
maps.  In the case of functor subtyping, this requires devising an untyped
semantics for programs that makes fmap into an inclusion \[
  \llbracket A \to B \rrbracket \subseteq \llbracket \F A \to \F B \rrbracket
\]
while still providing a sound model of the rest of the type system. This is an
unusual requirement, to say the least, and will require further research.

\section{Related Work}
Promoting fmap to a coercion has some similarity with work on effect systems,
where programs are permitted to run in an effect bounded below by the
effects they actually require. Effect systems may exhibit coherence if liftings
between effects do not commute. This issue has been addressed by Biernacki and
Polesiuk~\cite{DBLP:journals/lmcs/BiernackiP18}, who use a step-indexed logical
relation atop an operational semantics to establish the equivalence of terms
typed under different derivations.

The categorical point of view on implicit coercions appears to have originated
with Reynolds~\cite{reynolds80}, but we address an issue left unhandled in that
paper. He begins with a system of coercions that has at most one coercion
between any two types and proceeds to prove that certain term-level operations
defined at each type, like addition, commute with the coercions; this
establishes the coherence of terms built from basic operations in the presence
of subtyping. Our theorem takes a step back and begins with a possibly
incoherent system of declarative coercions. We show our system of normal
coercions has at most one coercion between any two types, but we also show that
its equational theory matches the equational theory of the original set of
coercions. Instead of checking that it commutes with term level operators, we
check that it commutes with the operations of the declarative coercion algebra.

Our application of normalization by evaluation to a coherence problem is
certainly precedented, although we are unaware of any applications to
algorithmic subtyping. We were particularly inspired by the coherence proof for
monoidal categories of Beylin and Dyjber~\cite{beylin95}, which recovers an old
result of Mac Lane from a proof of normalization for monoids. In a sense, a
monoid is a single-sorted category (or a category is a many-sorted monoid); our
normalization of terms involving identities (reflexivity proofs) and
compositions (transitivity proofs) bears formal similarities to Beylin and
Dyjber's proof.

Allais~et~al.~\cite{allais2025frex} describe Frex, a suite of tools for working
with single-sorted algebraic theories using normalization by evaluation.  An
extension of Frex to multi-sorted algebraic theories, as proposed by Allais and
an overlapping set of authors~\cite{allais2023}, would subsume our development
and make it easier to add new coercions and types to the system without tedious
reproving and refactoring.

\section{Conclusion}
We have presented a subtyping judgment for statically inferring silent uses of
the fmap combinator in monomorphic functional programs.  Our system uses
coercive subtyping, which treats fmap as a coercion that may be inserted
wherever the types involved make it make sense. To keep program meaning stable
in the face of this potentially intrusive and nondeterministic procedure, we
proved coherence of subtyping derivations using a new approach we call
\emph{coherence by normalization}.  All our definitions and proofs were checked
in Agda.
